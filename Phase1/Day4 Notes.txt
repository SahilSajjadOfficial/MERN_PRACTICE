CONCEPT 1: HIGH-ORDER ARRAY METHODS
-----------------------------------------------------------------------
The 'Why': Replaces manual for-loops. Introduces declarative programming
(telling JavaScript *what* to do, not the mechanical steps of *how*).

1. .filter()
- Purpose: Keeps items that pass a true/false condition; throws away the rest.
- Returns: A new, potentially shorter array.
- Syntax: array.filter(item => item.condition === true)

2. .map()
- Purpose: Transforms every item in an array into something else.
- Returns: A new array of the exact same length.
- Syntax: array.map(item => item.property)
- With Destructuring: array.map(({ property }) => `Value: ${property}`)

3. .reduce()
- Purpose: Squashes an entire array down into one single value (like a sum).
- Returns: A single value (number, string, object, etc.).
- Critical Rule: Always provide the starting value (e.g., 0) at the end.
- Syntax: 
  array.reduce((accumulator, currentItem) => {
      return accumulator + currentItem.value;
  }, 0);

* LESSON LEARNED (The Parenthesis Trap):
When chaining or writing .reduce(), ensure the arrow function stays INSIDE 
the method's parentheses. 
Wrong: .reduce((total, item)) => { ... }
Right: .reduce((total, item) => { ... }, 0)

CONCEPT 2: LEXICAL SCOPING & CLOSURES
-----------------------------------------------------------------------
The 'Why': JavaScript historically lacked private variables. Closures allow 
you to create a "private" memory vault that only specific functions can 
access, preventing the global application from accidentally overwriting state.

The 4 Pillars of a Closure:
1. The Vault: An outer function to establish a boundary.
2. The Treasure: A private variable (let count = 0) inside the outer function.
3. The Keyhole: An inner function that modifies the private variable.
4. The Export: Returning the inner function to the outside world.

* ARCHITECTURAL SKELETON (ID Generator):
function createIDGenerator(prefix) {
    let count = 0; // Protected State
    
    return function() { // The Closure
        count++;
        return `${prefix}_${count}`;
    };
}


-----------------------------------------------------------------------
CONCEPT 3: BASIC OBJECT-ORIENTED PROGRAMMING (ES6 CLASSES)
-----------------------------------------------------------------------
The 'Why': Bundles related data (state) and actions (methods) into a single 
entity. Crucial for database models and architectural system logic.

The Rules of State (this):
- The `constructor` runs once when the object is created to set initial state.
- Inside class methods, you MUST use `this.propertyName` to access or modify data.
- Never use `let` or `const` inside a method to update state; that creates a 
  temporary local variable that gets destroyed when the method finishes.

* ARCHITECTURAL SKELETON (State Management):
class Wallet {
    constructor(ownerName, initialBalance) {
        this.ownerName = ownerName;
        this.balance = initialBalance; // Initializing state
    }

    deposit(amount) {
        // Mutating actual state, NOT using 'let newBalance ='
        this.balance = this.balance + amount; 
    }

    getSummary() {
        return `${this.ownerName}'s balance is $${this.balance}`;
    }
}

MASTER COMBINATION: THE DATA PIPELINE
-----------------------------------------------------------------------
Applying Phase 1 concepts to a real-world system architecture.
Target -> Filter -> Map -> Return

class ReviewAnalyzer {
    constructor(reviews) {
        this.reviews = reviews; // Database data attached to the instance
    }

    getVerifiedSummaries() {
        // 1. Target the class state explicitly
        return this.reviews
            // 2. Filter for boolean truth
            .filter(review => review.isVerified === true)
            // 3. Map with ES6 Destructuring
            .map(({reviewer, score}) => `${reviewer} gave a score of ${score}`);
    }
}
