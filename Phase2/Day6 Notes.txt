CONCEPT 1: RENDERING LISTS & KEYS
-----------------------------------------------------------------------
The 'Why': A database returns arrays of data. We must dynamically generate
UI components for each item in that array without writing redundant code.

The Plural/Singular Rule:
- Target the plural array (users)
- Name the parameter singular (user)

The Syntax Blueprint:
{users.map((user) => (
    <UserCard 
        key={user._id}       // CRITICAL: React needs a unique ID for performance
        name={user.name}     // Mapping object properties to component props
    />
))}

* LESSON LEARNED (The Parenthesis Trap):
The arrow function's implicit return MUST be completely inside the .map() 
parentheses.
Wrong: {array.map(item)} => (...)
Right: {array.map((item) => (...))}


-----------------------------------------------------------------------
CONCEPT 2: CONDITIONAL RENDERING
-----------------------------------------------------------------------
The 'Why': UIs must react to data. An unpaid invoice looks different 
than a paid invoice. 

The Syntax (Ternary Operator):
{condition ? "What happens if true" : "What happens if false"}

Example:
<button>
    {isBooked ? "Cancel Request" : "Book Now"}
</button>


-----------------------------------------------------------------------
CONCEPT 3: CONTROLLED COMPONENTS & FORMS
-----------------------------------------------------------------------
The 'Why': The browser natively tries to control form inputs and refresh 
the page on submit. React must hijack this process so the component's 
state remains the single source of truth.

The 3 Steps to Control an Input:
1. Initialize state for the input: const [email, setEmail] = useState("")
2. Bind the UI to the state (Two-Way Binding):
   <input 
      value={email} 
      onChange={(e) => setEmail(e.target.value)} 
   />
3. Handle the submission on the <form>, NOT the <button>:
   <form onSubmit={handleSubmit}>

* LESSON LEARNED (Preventing the Refresh):
The very first line of a submit handler MUST be e.preventDefault(); to 
stop the browser from wiping your application state.

Example Submit Handler:
const handleSubmit = (e) => {
    e.preventDefault();
    console.log("Form Submitted:", email);
};
